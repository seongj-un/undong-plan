# 오늘의 운동 부위와 기구 추천 프로젝트 개요서

운동을 처음 시작한 사람이 오늘 운동할 부위와 사용할 기구를 찾도록 돕는 웹 서비스다. 현재는 문서 초안, 부위·기구 탐색·운동 상세·오늘의 추천의 로컬 정적 화면, API 명세의 서버 API 구현이 있다. 화면과 서버 API는 아직 연결하지 않았다.

## 해결할 문제와 제안하는 가치

검증할 제품 가설은 “초보자가 운동 부위와 기구를 함께 이해하면 오늘 사용할 기구를 선택하기 쉬워진다”이다. 사용자 조사 결과나 효과 측정 자료는 아직 없으며, 효과를 확정하지 않는다.

첫 버전은 로그인 없는 부위·기구 안내와 규칙 기반 추천으로 사용자 확인을 받았다. 사용 가능한 기구와 제외할 부위를 입력하고, 추천 결과에서 선택 이유와 상세 안내를 확인하는 세부 흐름을 제안한다.

| 기구 사진과 별칭으로 기구 찾기 | AI 챗봇과 AI 추천 |

| 기구 상세와 출처가 있는 사용 안내 | 카메라 기구 인식과 자세 분석 |

‘오늘’은 사용자가 현재 입력한 조건으로 받는 추천을 의미한다는 초안이다. 날짜별 자동 변경이나 주간 운동 계획은 포함하지 않는 방향을 제안하며, 필요 여부를 사용자에게 확인한다.

## 기술과 운영 결정 상태

로컬 화면은 기존 실행 기준에 따라 HTML·CSS·브라우저 JavaScript를 사용한다. 서버 API는 Node.js 표준 라이브러리만으로 `server/server.js`에 구현했으며 외부 패키지는 없다. 프레임워크, 데이터베이스, 배포 환경, 인증 방식, AI 모델 및 서비스 외부 연동은 미정이다. API의 HTTP·JSON 표현은 인터페이스 초안이며 특정 구현 기술 선택이 아니다.

새 기술 도입 전 사용자에게 후보 기술, 선택 이유, 비용과 대안을 제시하고 답변을 받는다. 그 결과는 `log.md`에 기록한다. 2026-09-30 서버 기술 질문은 질문 창 내부 오류로 사용자에게 전달되지 않았고, ‘전부 구현해’ 요청에 따라 기본안(Node.js 표준 라이브러리)을 적용했다. 대안은 Python 표준 라이브러리 서버 또는 서버를 추가하지 않는 것이었다. 사용자 답변을 받지 않았으므로 아래 결정 질문으로 다시 확인한다. 일정, 예산, 운영 담당자와 운동 콘텐츠 검수 담당자는 아직 알 수 없다.

## 현재 구현과 실행

- [화면 진입점](../index.html)을 브라우저에서 직접 연다. 프로젝트 폴더의 macOS 터미널에서 `open index.html`, Windows 명령 프롬프트에서 `start index.html`로 실행할 수 있다.
- F01: 7개 부위 분류와 전체 선택. 원문 대상 부위에 해당하는 운동·기구를 표시하고 미등록 부위는 빈 결과를 안내한다.
- F02: 기구 3개의 이름·한글 및 영문 별칭 검색, 초기화, 빈 결과와 상세 안내. 사진은 사용 권한 미확인으로 미제공한다.
- F03: 운동 3개의 부위·기구·한국어 사용 순서·주의점·출처·확인일·검수 대기 상태를 표시한다.
- 초기 운동은 체스트 프레스·랫 풀다운·레그 프레스다. 이는 화면 구현용 예시이며 전체 공개 카탈로그 규모를 확정한 결정은 아니다.
- 출처를 확인한 안내 초안을 표시하며 전문가 검수, 개인별 적합성, 보조 부위는 미정이다. 검수 완료 운동으로 표현하지 않는다. 서버 공개 카탈로그와 서버 추천에는 쓰지 않고, 로컬 화면 추천에서만 ‘검수 전 초안’ 표시와 함께 미리보기 후보로 쓴다(기본안 적용·사용자 확인 대기).
- F04~F06: 오늘의 추천 탭과 첫 화면의 ‘오늘의 추천 받기’·‘부위·기구 둘러보기’ 진입. 기구 확인 여부(필수), 사용할 수 있는 기구, 선호·제외 부위, 최대 추천 수 1~3개를 입력하고, [기획서](planning.md)의 추천 규칙으로 운동 카드·추천 이유·예외 안내를 표시한다. 계산은 `recommend.js`에서 하며 입력과 결과를 저장하지 않는다.
- 서버 API: 프로젝트 루트에서 `node server/server.js`로 `http://127.0.0.1:8787/api/v1`에 실행하는 선택 서버. 검수 완료 운동만 공개하므로 현재 운동 목록은 비어 있고 기구를 확인한 추천은 `no_candidates`다. 자동 테스트는 `node --test "server/*.test.js"`. 세부 동작은 [API 명세서](api-spec.md)의 구현 참고 절에 둔다.
- 로그인, AI 추천, 저장, 사진, 패키지 설치, 배포, 화면과 서버 API의 연결은 현재 구현에 포함되지 않는다.
- 직접 브라우저 검증 결과와 반복 수정 여부는 [반복 기록](../loop-log.md)을 참고한다. 조회 기능은 macOS Codex 내장 브라우저의 임시 HTTP 미리보기에서 44개 검증을 통과했으며 앱 코드 수정은 없었다. 추천 기능은 macOS Claude 데스크톱 앱 내장 브라우저의 임시 HTTP 미리보기에서 시나리오 11개와 실제 클릭·회귀·반응형 확인을 통과했고, 브라우저 실패 1건과 코드 리뷰 지적 3건을 고쳤다. 두 검증 모두 Chrome `file:` 직접 실행 검증과는 구분한다.

## 문서 초안의 완료 기준과 현재 구현 확인

- 세 문서와 `log.md`가 작성되어 있다.
- 사용자 요청, 제품 제안, 확인 대기 항목을 구분한다.
- 기획서의 기능과 API의 요청·응답이 일치한다.
- 외부 운동 정보에 확인한 출처와 확인일을 표기한다.
- 최초 문서 작업은 코드 구현·설치·배포 없이 완료했다. 이후 사용자 요청으로 조회 기능 3개, 이어서 추천 F04~F06과 서버 API를 구현했다. 패키지 설치·배포는 진행하지 않았다.
- 현재 구현은 [작업 규칙](../AGENTS.md)의 확인 절차 1~9번을 모두 적용한다. 서버 API는 자동 테스트(`node --test "server/*.test.js"`)로 따로 확인하며 브라우저 확인과 구분한다.

서비스의 효과, 사용자 수, 출시일과 운영 비용은 현재 알 수 없다. 개발과 사용자 검증을 마친 뒤 별도로 판단한다.
